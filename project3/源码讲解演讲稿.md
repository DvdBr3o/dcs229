## 正式讲稿

### 0. 开场（0:00–0:40）

【画面】文件开头，显示 import 和文件说明。

【口播】各位老师、同学，大家好。我负责 project3 的源码部分。这个项目做的是亚洲人脸的肤色分割：输入一张 RGB 照片，输出一张只保留肤色、其余像素变黑的图。整个脚本只有 `colorspace_split.py` 一个文件，大约 350 行。它没有用 OpenCV，而是用 NumPy 把颜色空间转换、阈值判断和中值滤波一步步写出来。今天我按代码的执行顺序讲，重点放在三个地方：旋转椭圆判据、二值中值滤波，以及统一接口的设计。

### 1. 先看整体：一条五步流水线（0:40–2:00）

【画面】滚动代码，依次指 `Split`、6 个子类、`median_filter_mask`、`colorspace_split`、`main`。

【口播】先不要急着看公式，先看结构。整个文件可以分成五块：第一块是颜色空间转换函数；第二块是 `Split` 抽象类和六个具体分割器；第三块是中值滤波；第四块是 `colorspace_split`，负责把掩膜应用到图像；最后是演示参数和 `main`。

不管中间换成 YCbCr、HSV 还是 LAB，所有分割器都遵守同一个约定：输入 `H×W×3` 的图像，输出 `H×W` 的布尔掩膜，`True` 表示肤色。后面的滤波、上色都只跟这个布尔矩阵打交道。这一点很重要，它让颜色空间和后续处理解耦。

数据流可以写成这样：

```text
RGB 图像 → 颜色空间转换 → 判决边界 → H×W bool → 中值滤波 → 应用掩膜 → 输出
```

### 2. 输入归一化（2:00–2:40）

【画面】停在 25–34 行 `_as_float_rgb`。

【口播】所有分割器第一步都调用 `_as_float_rgb`。它做三件事：灰度图复制成三通道；RGBA 丢掉 alpha；最后统一转成 `float32`。为什么不用 8 位整数？因为后面的公式有小数、有除法，整数会截断。为什么不用 `float64`？颜色只有 8 位，`float32` 的精度足够，内存和带宽省一半。

这里还有一个约定：YCbCr 和归一化 RGB 直接在 0–255 上算；HSV 和 LAB 会自己再除以 255。看代码时不要混。

### 3. 颜色空间转换（2:40–7:00）

【画面】停在 37–44 行。

#### 3.1 YCbCr（2:40–3:40）

【口播】先看 YCbCr，BT.601 全范围。三行公式：

```text
Y  = 0.299R + 0.587G + 0.114B
Cb = 128 - 0.168736R - 0.331264G + 0.5B
Cr = 128 + 0.5R - 0.418688G - 0.081312B
```

这三行系数有两个特点：第一行加起来是 1，后两行加起来是 0。所以灰色像素 `R=G=B` 会得到 `Y=R`、`Cb=Cr=128`。这就是我们说“色度以 128 为中心”的原因。

为什么要换到 YCbCr？因为 RGB 里亮度和颜色是耦合的：光照一变，三个通道一起变。换到 YCbCr 后，亮度在 Y，颜色在 Cb/Cr，肤色在 Cb/Cr 平面上会聚成一小簇，后面就可以用框或椭圆去圈它。

代码上没有循环，就是 `r, g, b = rgb[..., 0], ...` 把三个通道拆出来，整幅图一次算完。

#### 3.2 HSV（3:40–5:00）

【画面】停在 47–67 行。

【口播】HSV 的思路更直观：H 是色相，S 是饱和度，V 是明度。代码先算最大值 M、最小值 m 和差 Δ，然后根据哪个通道最大，分三种情况算 H：

```text
H = 60° × ((G-B)/Δ mod 6)     若 M=R
H = 60° × ((B-R)/Δ + 2)       若 M=G
H = 60° × ((R-G)/Δ + 4)       若 M=B
S = Δ / M
V = M
```

实现上有三个细节。第一，它没有写 if-else，而是用 `red/green/blue` 三个布尔掩膜分别算，再写回 `hue`，这样是向量化的。第二，红色分支用了 `% 6`，因为 `G-B` 可能是负的，取模以后角度会绕回 `[0,6)`。第三，当两个通道并列最大时，比如黄色 `R=G=max`，`red` 和 `green` 都成立，后面赋值的 `green` 会覆盖 `red`，结果正好是 60°；青色得到 180°，品红得到 300°。这个赋值顺序刚好把并列情况处理正确。

还有 `np.divide(..., where=maximum > 1e-8)`，避免黑色像素除以 0。H 是角度，S 和 V 是 0 到 1。

要注意，色相是环形的。当前 HSV 分割只取 0° 到 50°，没有处理 350° 附近的红色；对这批亚洲肤色够用，但换素材要注意。

#### 3.3 CIELAB（5:00–6:30）

【画面】停在 70–100 行。

【口播】LAB 是这几个转换里最麻烦的，但步骤很清楚。第一步，除以 255。第二步，sRGB 反 gamma：小于 0.04045 时除以 12.92，否则用 `((c+0.055)/1.055)^2.4`。这一步不能省，因为 sRGB 是编码过的，直接做矩阵乘法相当于在非线性空间里混色。第三步，乘 D65 矩阵转到 XYZ。第四步，除以白点。第五步，分段立方根：

```text
f(t) = t^(1/3)              t > ε
f(t) = (κt + 16)/116        否则
ε = 216/24389, κ = 24389/27
```

最后得到 `L* = 116f(Y)-16`、`a* = 500(f(X)-f(Y))`、`b* = 200(f(Y)-f(Z))`。

我们真正只用了 `a*` 和 `b*` 平面，`L*` 只作为亮度门限。为什么要这么麻烦？因为 LAB 更接近人眼感知，肤色在 `a*/b*` 平面上更容易用一个椭圆圈住。但固定 `L*` 门限也有代价：侧光、阴影、额头高光会被切掉，人脸内部会出现空洞。

#### 3.4 归一化 RGB（6:30–7:00）

【画面】停在 103–109 行。

【口播】最后一个空间是归一化 RGB：`r=R/(R+G+B)`，`g=G/(R+G+B)`。它把整体亮度除掉了，理论上只留色度。分母接近 0 时不稳定，所以用 `np.divide(..., where=total > 1e-6)` 保护；分割时还要求 `R+G+B >= 30`，把接近黑色的像素排除。它的缺点是不同颜色可能投影到同一个 `(r,g)` 点，浅色衣服和灰背景容易混进来，所以只作为对照。

### 4. 判决边界（7:00–11:00）

【画面】停在 117–119 行 `Split`。

【口播】有了颜色空间，下一步是“怎么圈”。六个分割器都继承 `Split`，只实现一个 `mask` 方法。我们先看两个简单的，再看重点椭圆。

#### 4.1 RGB 球与矩形框（7:00–8:00）

【画面】122–157 行。

【口播】`SphereSplit` 最直接：以 `avg` 为球心，算 RGB 欧氏距离，小于 `thres` 就算肤色。默认球心是整幅图的平均色，半径 100。问题也在这里：背景占比大时，平均色被拉向背景；灰墙、白衬衫和肤色的 RGB 距离可能很小。所以它不是肤色检测器，更像“接近平均色的区域检测器”。

`YCbCrBoxSplit` 是三个区间同时满足：`Cb` 在 77 到 127，`Cr` 在 133 到 173，`Y` 至少 40。代码就是几个比较用 `&` 连起来。这里有一个 Python 细节：`&` 的优先级高于比较运算符，所以每个比较都要加括号，不能写成 `a >= 0 & b <= 1`。

矩形框的优点是简单、参数少；缺点是四个角会伸到肤色簇外面，遇到暖色背景容易误检。

#### 4.2 旋转椭圆（8:00–10:10，重点）

【画面】停在 160–184 行；【板书】画 `d → u,v → 单位圆`。

【口播】重点来了，YCbCr 椭圆。它用中心、两个半轴和旋转角来描述边界，比矩形多了方向和长短轴的信息，边界也更贴合肤色簇。

数学上分三步。第一步平移：`dcb = Cb - Cb0`，`dcr = Cr - Cr0`，把中心移到原点。第二步旋转：

```text
u =  cosθ·dcb + sinθ·dcr
v = -sinθ·dcb + cosθ·dcr
```

这是把点旋转到椭圆的主轴坐标系。注意它是坐标轴的负 θ 旋转，等价于椭圆本身相对 Cb 轴正 θ 旋转。第三步归一化：

```text
(u/a)² + (v/b)² <= 1
```

也就是把椭圆压成单位圆，再看点在不在里面。

写成矩阵就是 `dᵀ Rᵀ diag(1/a², 1/b²) R d <= 1`，它等价于一个马氏距离。实现上三个好处：第一，不用开方，直接比较平方半径和 1；第二，不用显式构造协方差矩阵，`u/v` 两个中间量就完成了旋转和缩放；第三，没有逐像素循环，全是 `H×W` 数组运算。

默认参数是中心 `(110,150)`、半轴 `(26,20)`、旋转 `15°`。15° 让长轴沿着肤色簇在 Cb/Cr 平面上的倾斜方向。和矩形框比，椭圆把四个角削掉了，所以更紧；和 RGB 球比，它只在色度平面上判断，亮度由 Y 单独门限，所以更稳。

#### 4.3 LAB 椭圆与归一化 RGB（10:10–11:00）

【画面】212–265 行。

【口播】LAB 椭圆和 YCbCr 椭圆结构完全一样，只是把 `Cb/Cr` 换成 `a*/b*`，中心 `(14,18)`，半轴 `(13,13)`，`L*` 做 25 到 100 的门限。这里有一个细节：两个半轴相等时，椭圆退化成圆，旋转 30° 其实不起作用；如果希望它真正是椭圆，需要把半轴改成不同的值。这是一个可以改进的点。

归一化 RGB 就是矩形框，`r` 在 0.33 到 0.48，`g` 在 0.28 到 0.40，再用 `R+G+B >= 30` 排除暗像素。它对亮度不敏感，但会把浅色衣服和灰背景选进来。

### 5. 中值滤波（11:00–12:40）

【画面】停在 273–282 行。

【口播】分割出来的掩膜会有孤立噪点：一个像素被误判成肤色，周围都不是。后处理用 5×5 中值滤波。

二值情况下，中值滤波就是多数投票：25 个像素里，至少 13 个是 1，输出才是 1。所以不需要真的排序，直接求窗口均值，大于 0.5 就是多数。

代码只有四行：

```python
pad = size // 2
padded = np.pad(mask.astype(np.uint8), pad, mode="edge")
windows = np.lib.stride_tricks.sliding_window_view(padded, (size, size))
return windows.mean(axis=(-1, -2)) > 0.5
```

形状上，`H×W` 先 pad 成 `(H+2p)×(W+2p)`，再用 `sliding_window_view` 变成 `H×W×5×5` 的视图，最后对最后两维求均值。`sliding_window_view` 不复制数据，它只是用 stride 造出窗口视图，真正分配内存的是后面的 `mean`。

边界用 `mode="edge"`，把最外圈复制到外面。如果补 0，贴边的实心肤色区域会被外部的 0 投票投掉，边缘会被腐蚀。偶数窗口会平票，所以代码直接拒绝；`size <= 1` 表示关闭滤波。

顺便说一句，Pillow 的 `MedianFilter` 也能做，而且它内部也会做边缘扩展；我们自实现主要是因为它直接处理布尔掩膜、保持 NumPy 向量化，而且算法过程完全可见。

### 6. 应用掩膜与 alpha（12:40–13:20）

【画面】停在 285–300 行。

【口播】最后是 `colorspace_split`。它把原图转成 RGB 数组，算掩膜，按需滤波，然后：

```python
output = np.where(mask[..., None], view, 0).astype(np.uint8)
```

`mask[..., None]` 把 `H×W` 变成 `H×W×1`，再和 `H×W×3` 广播，三个通道用同一个掩膜。`True` 保留原色，`False` 置黑。

如果原图有 alpha，函数会把 alpha 单独取出来，最后用 `np.dstack` 拼回去；alpha 不参与颜色转换，也不参与滤波。

这里有一个小冗余：`main` 为了显示掩膜先算了一次 `mask`，`colorspace_split` 内部又算了一次。功能上没问题，但同一张图做了两遍颜色变换和滤波。可以抽一个 `apply_mask(view, mask)`，让 `colorspace_split` 接受预计算掩膜。

### 7. 接口设计（13:20–14:00）

【画面】回到 117 行。

【口播】最后说设计。`Split` 是一个抽象基类，只规定 `mask` 方法；六个具体类各自封装颜色空间和阈值。这是典型的策略模式：调用方只依赖 `Split`，不知道背后是 YCbCr 还是 LAB。

好处是新增一种判据只需要写一个新类，再改演示脚本里的 `SPLIT` 常量，I/O 和绘图代码完全不用动。阈值都放在构造函数里，换素材只改参数。代价是每个分割器都会重新做一次颜色转换；如果要批量比较六种判据，可以缓存转换结果。

### 8. 结果与收尾（14:00–15:00）

【画面】切到 `public/compare_asian_1.png` 或 `split_scores.csv`。

【口播】结果上，我们从 15 张候选图里保留了三张，对应三种最稳定的判据。

`asian_1` 是灰棚拍、浅色衣服，用 YCbCr 椭圆：选中 23.46%，四角误检 0，人脸框覆盖 77.23%。同一张图上 RGB 球选中 75.38%，四角误检 86.66%，对比很明显。

`asian_6` 是低照度侧脸，用 YCbCr 矩形框：选中 32.97%，人脸覆盖 84.30%，四角误检 8.82%。LAB 在这张图上人脸覆盖只有 66.98%，因为固定亮度门限把脸颊切出了空洞。

`asian_13` 是灰色背景、黑发黑衫，用 HSV：选中 14.86%，四角误检 0，人脸覆盖 41.72%。

所以结论是：没有一种颜色空间在所有场景下都最好。灰棚拍适合 YCbCr 椭圆，低照度侧脸适合矩形框，单色背景适合 HSV。固定阈值仍然需要按素材调参；后续可以加人脸检测或空间先验、自适应阈值、形态学和连通域清理。

## Q&A 备用回答

**Q：为什么不用 OpenCV？**  
A：课程重点是讲清楚颜色空间和判决边界。自己写公式、阈值和滤波，代码路径透明，依赖也少；工程上当然可以用 OpenCV。

**Q：为什么用 BT.601 全范围，而不是 16–235？**  
A：输入是普通 8 位 sRGB PNG，没有视频范围信息；full-range 的 Y 覆盖 0–255，Cb/Cr 以 128 为中心，和常用肤色阈值一致。

**Q：椭圆为什么不用开方？**  
A：只需要判断点在椭圆内还是外，平方半径和 1 比较就够了，省掉 `sqrt`。

**Q：中值滤波为什么能去噪？**  
A：二值中值就是多数投票。孤立白点周围白点少，投不过半被清掉；实心区域内部白点多，保留。

**Q：为什么边界用 edge padding？**  
A：补 0 会把图像外侧当成背景，贴边的实心区域会被腐蚀；复制边缘可以保持投票结果，输出尺寸也不变。

**Q：为什么用 float32？**  
A：8 位颜色用 float32 精度足够，比 float64 省一半内存和带宽；整数会截断小数。

**Q：LAB 的旋转角为什么没效果？**  
A：默认半轴是 `(13,13)`，椭圆退化成圆，旋转圆不改变形状。要看到效果，需要把两个半轴设成不同值。

**Q：RGB 球为什么失败？**  
A：球心取整幅图平均色，背景占比大时被拉向背景；半径 100 又很大，结果把背景和暗部一起圈进去。

**Q：HSV 的色相跨 0° 怎么办？**  
A：当前只判断 0°–50°，没有实现回绕；要覆盖 350°–360°，需要加 `wrap_hue` 分支：`(H >= lo) | (H <= hi)`。

**Q：为什么 mask 算了两次？**  
A：一次用于显示，一次在 `colorspace_split` 内部用于生成结果；可以抽 `apply_mask` 复用。

**Q：复杂度是多少？**  
A：颜色转换和阈值判断是 `O(H×W)`；中值滤波是 `O(H×W×k²)`，5×5 时 k²=25。

**Q：报告里说 Pillow 边界补零，但代码不是这样？**  
A：以代码为准。Pillow 的 `RankFilter` 会先 `expand` 做边缘复制；我们自实现的理由主要是布尔掩膜、向量化和算法透明，不是“Pillow 会补零”。

**Q：报告里的 `wrap_hue` 在代码里没有？**  
A：报告代码块和实际脚本存在版本差，实际脚本没有实现。要覆盖 350°–360° 的红色，可以加一个分支：`hue_ok = (H >= lo) | (H <= hi)`。
