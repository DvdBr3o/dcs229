## 0. 一分钟总览

一句话：**把肤色分割拆成「颜色空间转换 → 判决边界 → 布尔掩膜 → 后处理」四步，所有像素运算都用 NumPy 向量化完成。**

- 输入：`H×W×3` 的 8 位 RGB 图像。
- 中间量：`H×W` 的布尔掩膜，`True` 表示肤色。
- 输出：肤色保留原色，其余置黑；alpha 原样透传。
- 6 个分割器都实现同一个接口 `Split.mask(img)`。
- 涉及 5 个颜色空间：RGB、YCbCr、HSV、CIELAB、归一化 RGB；组合出 6 种判据。
- 没有 Python 逐像素循环；颜色变换、阈值判断、滤波全部是数组运算。
- 后处理是 `5×5` 布尔中值滤波，本质是**多数投票**；边界用 **edge padding**。

**讲课主线：**

```
为什么换颜色空间 → 怎么换 → 怎么判 → 怎么清理噪点 → 结果与选型
```

## 2. 数据流

```
PIL Image
  └─ convert("RGB") ──────────────► H×W×3 uint8
       └─ _as_float_rgb ──────────► H×W×3 float32
            └─ rgb_to_* ──────────► H×W×3（目标颜色空间）
                 └─ Split.mask ───► H×W bool
                      └─ median_filter_mask ─► H×W bool
                           └─ np.where(mask[...,None], rgb, 0) ─► H×W×3 uint8
                                └─ 拼回 alpha ─► PIL Image
```

三个不变量：

1. **掩膜始终是 `H×W` 布尔数组**，不携带颜色信息。
2. **颜色空间转换只发生在各个 `Split` 内部**，`colorspace_split` 不关心具体是哪种空间。
3. **应用掩膜只做一次**：`np.where` 按像素三通道同时选择保留或置黑。

## 3. 输入归一化：`_as_float_rgb`

```python
def _as_float_rgb(img: np.ndarray) -> np.ndarray:
    rgb = np.asarray(img)
    if rgb.ndim == 2:                      # 灰度图
        rgb = np.repeat(rgb[..., None], 3, axis=-1)
    if rgb.shape[-1] == 4:                 # RGBA：丢掉 alpha
        rgb = rgb[..., :3]
    if rgb.shape[-1] != 3:
        raise ValueError(...)
    return rgb.astype(np.float32, copy=False)
```

要点：

- 兼容灰度图、RGB、RGBA 三种输入。
- 统一成 **float32**：公式里会有小数和除法，整数会截断或溢出；float32 精度足够，内存和带宽比 float64 省一半。
- `copy=False`：如果输入已经是 float32，就尽量不复制。
- 约定：**后续 YCbCr / 归一化 RGB 使用 0–255 范围**；HSV / LAB 自己再除以 255。

## 4. 颜色空间转换

### 4.1 YCbCr（BT.601 全范围）

```python
y  = 0.299*r + 0.587*g + 0.114*b
cb = 128.0 - 0.168736*r - 0.331264*g + 0.5*b
cr = 128.0 + 0.5*r - 0.418688*g - 0.081312*b
```

三个关键观察：

- 系数行分别满足「和为 1」「和为 0」「和为 0」，所以灰色 `R=G=B` 会得到 `Y=R`、`Cb=Cr=128`。
- 这是 **full-range**（0–255）而非视频范围的 16–235，适合普通 8 位 PNG。
- 亮度 `Y` 与色度 `Cb/Cr` 分离，肤色在 `Cb/Cr` 平面上聚成一小簇，因此可以用框或椭圆描述。

代码用 `r, g, b = rgb[..., 0], rgb[..., 1], rgb[..., 2]` 取通道，`...` 保留前面的 `H×W` 维，整幅图一次算完。

### 4.2 HSV

```python
M = max(R, G, B)
m = min(R, G, B)
Δ = M - m

H = 60° ×
    ((G-B)/Δ) mod 6     若 M = R
    (B-R)/Δ + 2         若 M = G
    (R-G)/Δ + 4         若 M = B

S = Δ / M                （M = 0 时 S = 0）
V = M
```

实现细节：

- 用三个布尔掩膜 `red/green/blue` 分别计算，再写回 `hue`，避免逐像素分支。
- 红色分支的 `% 6.0` 把负角度绕回 `[0, 6)`，再乘 60 得到 `[0, 360)`。
- **并列最大值的处理**：当 `R=G=max` 时，`red` 和 `green` 都成立，后面的 `green` 会覆盖 `red`，结果正好是 60°；`G=B=max` 得到 180°，`R=B=max` 得到 300°。赋值顺序在这里刚好把并列情况处理正确。
- `np.divide(..., where=maximum > 1e-8)` 避免黑色像素除以 0；`where` 不成立的位置保持 0。
- 输出范围：`H` 为角度，`S/V` 为 `[0,1]`。

注意：色相是**环形**的。当前 `HSVSplit` 的区间是 0°–50°，没有处理 350° 附近的红色回绕；对亚洲肤色通常够用，但换素材时要注意。

### 4.3 CIELAB（D65）

分五步：

1. `rgb / 255` 归一化到 `[0,1]`。
2. **sRGB 反 gamma 线性化**：

   ```python
   c <= 0.04045 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4
   ```

3. 线性 RGB → XYZ（D65 矩阵）：

   ```text
   X = 0.4124564 R + 0.3575761 G + 0.1804375 B
   Y = 0.2126729 R + 0.7151522 G + 0.0721750 B
   Z = 0.0193339 R + 0.1191920 G + 0.9503041 B
   ```

4. 除以白点 `(0.95047, 1.0, 1.08883)`。
5. 分段立方根：

   ```text
   f(t) = t^(1/3)                 若 t > ε
          (κt + 16) / 116         否则
   ε = 216/24389 ≈ 0.008856
   κ = 24389/27  ≈ 903.3

   L* = 116 f(Y) - 16
   a* = 500 (f(X) - f(Y))
   b* = 200 (f(Y) - f(Z))
   ```

为什么要反 gamma：sRGB 图像是**编码过**的，直接做矩阵运算相当于在非线性空间里混合颜色；先线性化，`a*/b*` 才有可比较的感知意义。

数值细节：

- `np.where` 会同时计算两个分支，但这里 `X/Y/Z` 非负，`cbrt` 不会遇到负数，安全。
- 实际只使用 `a*/b*` 平面做椭圆，`L*` 只作为亮度门限。

### 4.4 归一化 RGB

```python
r = R / (R + G + B)
g = G / (R + G + B)
```

- 理论上去掉整体亮度，只保留色度。
- 分母接近 0 时不稳定，所以用 `np.divide(..., where=total > 1e-6)` 保护。
- `ChromaticitySplit` 另外要求 `R+G+B >= 30`，把接近黑色的像素排除。
- 因为 `r+g+b=1`，只需要 `r,g` 两个坐标。
- 缺点：不同颜色可能投影到同一个 `(r,g)` 点；浅色衣服、灰色背景容易和肤色混在一起。

### 4.5 五种空间对比

| 颜色空间 | 使用的坐标 | 肤色先验 | 亮度是否分离 | 主要问题 |
| --- | --- | --- | --- | --- |
| RGB | R, G, B | 球 / 均值 | 否 | 亮度与色度耦合 |
| YCbCr | Y, Cb, Cr | 框 / 椭圆 | 是 | 阈值固定 |
| HSV | H, S, V | 框 | 部分 | H 环形、低饱和不稳定 |
| CIELAB | L*, a*, b* | 椭圆 | 是 | 固定 L* 门限会切掉阴影/高光 |
| 归一化 RGB | r, g | 框 | 是（理论） | 暗像素不稳、色度碰撞 |

## 5. 判决边界

### 5.1 RGB 球：`SphereSplit`

```python
avg = rgb.mean(axis=(0, 1)) if self.avg is None else self.avg
return np.linalg.norm(rgb - avg, axis=-1) < self.thres
```

数学形式：

```text
||p - μ||₂ < t
```

- `μ` 默认取**整幅图像的平均色**，`t=100`（RGB 欧氏距离，最大约 441）。
- 问题：背景占比大时，`μ` 被拉向背景；灰墙、白衬衫与肤色的 RGB 距离可能很小。
- 本质：它不是肤色检测器，而是「颜色接近图像平均值的区域检测器」。

### 5.2 YCbCr 矩形框：`YCbCrBoxSplit`

```python
return ((y >= y0) & (y <= y1)
        & (cb >= cb0) & (cb <= cb1)
        & (cr >= cr0) & (cr <= cr1))
```

- 三个分量各给一个区间，所有条件同时满足才选中。
- 默认：`Cb ∈ [77,127]`，`Cr ∈ [133,173]`，`Y >= 40`。
- 实现最简单、参数最少、可解释性强。
- 缺点：矩形框的四个角会伸到肤色簇之外，遇到暖色背景容易误检。

> Python 细节：`&` 的优先级**高于**比较运算符，所以每个比较都要加括号。写成 `a >= 0 & b <= 1` 会得到错误结果。

### 5.3 YCbCr 旋转椭圆：`YCbCrEllipseSplit`（重点）

代码：

```python
theta = np.deg2rad(self.rotation)
cos_t, sin_t = np.cos(theta), np.sin(theta)

dcb = cb - self.center[0]
dcr = cr - self.center[1]

u =  cos_t * dcb + sin_t * dcr
v = -sin_t * dcb + cos_t * dcr

radius = (u / self.axes[0]) ** 2 + (v / self.axes[1]) ** 2
return (radius <= 1.0) & (y >= y0) & (y <= y1)
```

分三步理解：

1. **平移**：`d = (Cb - Cb0, Cr - Cr0)`，把椭圆中心移到原点。
2. **旋转坐标**：把点旋转到椭圆的主轴坐标系。代码中的矩阵是

   ```text
   [u]   [ cosθ  sinθ ] [dcb]
   [v] = [-sinθ  cosθ ] [dcr]
   ```

   这是坐标轴的 **-θ** 旋转；等价于椭圆本身相对 `Cb` 轴 **+θ** 旋转。
3. **归一化**：`(u/a)² + (v/b)² <= 1`，把椭圆变成单位圆再判断。

矩阵形式：

```text
dᵀ Rᵀ diag(1/a², 1/b²) R d <= 1
```

它等价于一个**马氏距离**：

```text
dᵀ Σ⁻¹ d <= 1,   Σ = Rᵀ diag(a², b²) R
```

其中 `a、b` 是两个半轴长度，`θ` 是椭圆长轴相对 `Cb` 轴的夹角。

为什么这样写好：

- **不需要开方**：直接比较平方半径和 1，少一次 `sqrt`。
- **不需要显式协方差矩阵**：`u/v` 两个中间量就完成了旋转和缩放。
- **没有逐像素循环**：所有运算都是 `H×W` 数组操作。
- 参数有明确几何意义：中心、半轴、旋转角，便于按素材调参。

默认参数：中心 `(110,150)`、半轴 `(26,20)`、旋转 `15°`、`Y ∈ [30,255]`。  
`15°` 让长轴沿着肤色簇在 `Cb/Cr` 平面上的倾斜方向；椭圆比矩形更贴合数据，也比 RGB 球更聚焦在色度上。

### 5.4 LAB 椭圆：`LabEllipseSplit`

结构与 YCbCr 椭圆完全同构，只是：

```python
da = a  - center[0]   # center = (14, 18)
db = b  - center[1]
u  =  cos_t*da + sin_t*db
v  = -sin_t*da + cos_t*db
radius = (u/13)**2 + (v/13)**2
return (radius <= 1) & (lightness >= 25) & (lightness <= 100)
```

注意一个细节：默认半轴是 `(13,13)`，**两个半轴相等时椭圆退化成圆，旋转角 `30°` 实际上不起作用**。如果希望它真正呈椭圆形，应把两个半轴改成不同的值（例如 `(13,10)`）。

LAB 的问题：固定的 `L*` 门限会在侧光、阴影和额头高光处切掉肤色，导致人脸内部出现空洞。

### 5.5 归一化 RGB 框：`ChromaticitySplit`

```python
r, g = rgb_to_chromaticity(rgb)   # 去掉亮度
return ((rgb.sum(axis=-1) >= 30)
        & (r >= 0.33) & (r <= 0.48)
        & (g >= 0.28) & (g <= 0.40))
```

- 只使用 `r,g`，对整体亮度不敏感。
- 用 `min_sum=30` 排除接近黑色的像素。
- 缺点：浅色衣服、灰色背景会投影到与肤色接近的 `(r,g)` 区域，四角误检率通常较高。

### 5.6 参数默认值速查

| 类 | 关键参数 |
| --- | --- |
| `SphereSplit` | `avg=图像均值`，`thres=100` |
| `YCbCrBoxSplit` | `Cb 77–127`，`Cr 133–173`，`Y 40–255` |
| `YCbCrEllipseSplit` | 中心 `(110,150)`，半轴 `(26,20)`，旋转 `15°`，`Y 30–255` |

## 6. 中值滤波：布尔掩膜的多数投票

### 6.1 为什么中值等于多数投票

对二值信号，奇数窗口的中值就是「1 的个数是否超过一半」：

```text
5×5 窗口共 25 个像素，中值是排序后的第 13 个；
所以 1 的个数 >= 13 时输出 1，否则输出 0。
```

因此不需要真的排序，直接求均值再和 `0.5` 比较即可：

```python
windows.mean(axis=(-1, -2)) > 0.5
```

### 6.2 实现

```python
def median_filter_mask(mask: np.ndarray, size: int = 5) -> np.ndarray:
    if size <= 1:
        return mask
    if size % 2 == 0:
        raise ValueError(...)

    pad = size // 2
    padded = np.pad(mask.astype(np.uint8), pad, mode="edge")
    windows = np.lib.stride_tricks.sliding_window_view(padded, (size, size))
    return windows.mean(axis=(-1, -2)) > 0.5
```

形状变化：

```text
mask          H×W
pad(mode=edge) (H+2p)×(W+2p)        p = size//2
sliding_window H×W×size×size        # 视图，不复制数据
mean(-1,-2)   H×W                   # 窗口内 1 的比例
> 0.5         H×W bool              # 多数票结果
```

要点：

- **`sliding_window_view` 不复制数据**，只是用 stride 造出「每个像素一个窗口」的视图；真正分配内存的是后面的 `mean`。
- `mask.astype(np.uint8)` 让 padding 和均值计算更直接；布尔数组本身也能 pad，但转成 0/1 更直观。
- 偶数窗口会平票，所以直接拒绝；`size <= 1` 表示关闭滤波。
- 时间复杂度 `O(H×W×k²)`，5×5 时 `k²=25`，对 640×512 的图像约 800 万次加法，NumPy 足够快。
- 结果保持原尺寸 `H×W`，不会裁边。

### 6.3 为什么用 edge padding

如果边界补 0，图像边缘外侧会被当成「非肤色」：

```text
真实边界：  1 1 1 | 0 0 0 0 0   ← 外侧补 0
窗口投票：  边缘的 1 可能被外部的 0 投掉，实心区域被腐蚀
```

`mode="edge"` 把最外圈像素复制到外侧：

```text
真实边界：  1 1 1 | 1 1 1 1 1   ← 复制边缘
窗口投票：  贴边的实心区域仍然是多数，不会被误删
```

### 6.4 为什么不用 Pillow 的 `MedianFilter`

更准确的说法不是「Pillow 边界补零」——Pillow 的 `RankFilter.filter` 会先 `image.expand(margin)` 做边缘复制，再 `rankfilter`，实际也是 edge padding。自实现的主要理由是：

- 输入是**布尔掩膜**，不是 PIL 灰度图，省去 `L` 模式转换；
- 整幅图向量化，和后面的 NumPy 流程一致；
- 算法过程完全可见，适合课程讲解；
- 可以明确控制窗口大小和边界行为。

> 报告 `main.typ` 里「Pillow 在边界补零」的说法不准确，讲课时建议改成上面的理由。

### 6.5 滤波效果

- 去掉孤立的误检点（椒盐噪声）。
- 填补肤色区域内部的小空洞。
- 平滑边缘，但也会轻微磨圆尖角。
- `MEDIAN_SIZE=1` 关闭；`5` 是报告采用的默认值。

## 7. 应用掩膜与 alpha

```python
view = np.array(img.convert("RGB"))
mask = split.mask(view)
if median_size is not None:
    mask = median_filter_mask(mask, median_size)

output = np.where(mask[..., None], view, 0).astype(np.uint8)
```

关键点：

- `mask[..., None]` 把 `H×W` 变成 `H×W×1`，再和 `H×W×3` 广播，三个通道使用同一个掩膜。
- `np.where(mask[..., None], view, 0)`：`True` 保留原 RGB，`False` 置 0（黑）。
- `.astype(np.uint8)`：保证输出为 8 位。当前 NumPy 下 `np.where(bool, uint8, 0)` 通常已经返回 `uint8`，显式转换是为了不依赖版本/平台的类型推断。
- alpha 处理：

  ```python
  has_alpha = img.mode in ("RGBA", "LA") or "transparency" in img.info
  if not has_alpha:
      return Image.fromarray(output)
  alpha = np.array(img.convert("RGBA"))[..., 3]
  return Image.fromarray(np.dstack((output, alpha)))
  ```

  alpha 不参与颜色转换，也不参与滤波，原样拼回。

- `colorspace_split` 是纯函数：不修改输入数组，返回新的 PIL Image。

**一个小冗余**：`main()` 为了显示掩膜先算了一次 `mask`，`colorspace_split` 内部又算了一次。功能上没问题，但同一张图做了两遍颜色变换和滤波。可以重构成：

```python
def apply_mask(view, mask):
    return np.where(mask[..., None], view, 0).astype(np.uint8)
```

让 `colorspace_split` 接受可选的预计算掩膜。

## 8. 接口与设计

```python
class Split(ABC):
    @abstractmethod
    def mask(self, img: np.ndarray) -> np.ndarray: ...
```

这是典型的**策略模式**：

- `Split` 是抽象策略，只规定「输入图像，输出布尔掩膜」。
- 6 个具体类各自封装「颜色空间 + 判决边界 + 阈值」。
- `colorspace_split` 是上下文，只依赖 `mask`，不知道具体是哪种颜色空间。
- 新增一种判据，只需要写一个新类，再改演示脚本里的 `SPLIT` 常量，I/O 和绘图代码不变。

设计上的好处：

- **关注点分离**：颜色转换、判决、后处理、显示各自独立。
- **参数局部化**：所有阈值放在构造函数里，换素材时只改一个地方。
- **可测试**：`mask` 是纯函数，给定数组就有确定输出，容易做单元测试。
- **可扩展**：要加「椭圆 + 形态学」「自适应阈值」等，不需要动已有类。

代价：

- 每个 `Split` 都会重新做一次颜色转换；如果要在同一张图上比较 6 种判据，会重复计算。
- 阈值是硬编码的经验值，换一批素材仍可能需要调参。

## 10. 结果与选型

原始 15 张候选图经比较后保留 3 张，分别对应三种最稳定的判据：

| 素材 | split | 选中比例 | 人脸框覆盖 | 四角误检 |
| --- | --- | --- | --- | --- |
| `asian_1` | `ycbcr-ellipse` | 23.46% | 77.23% | 0.00% |
| `asian_6` | `ycbcr-box` | 32.97% | 84.30% | 8.82% |
| `asian_13` | `hsv` | 14.86% | 41.72% | 0.00% |

指标定义：

- **选中比例**：掩膜中 `True` 的像素占比。
- **人脸框覆盖**：手工近似人脸矩形内被选中的比例，衡量肤色保留。
- **四角误检**：图像四个 `80×80` 角落中被选中的比例，衡量背景误检。

三点结论：

1. **没有一种颜色空间在所有场景下最好**：灰棚拍选 YCbCr 椭圆，低照度侧脸选 YCbCr 框，单色灰背景选 HSV。
2. **RGB 球和归一化 RGB 容易失败**：前者把亮度和色度耦合，后者会把浅色衣服/灰背景投影到肤色附近。
3. **固定阈值有代价**：换一批素材仍可能需要调参；后续可以引入人脸检测/空间先验、自适应阈值、形态学和连通域清理。

## 12. 可能的提问与回答

**Q1：为什么不用 OpenCV 或现成的肤色检测？**  
A：本实验的重点是把颜色空间和判决边界讲清楚。自己实现公式、阈值和滤波，代码路径透明，依赖也只有 NumPy/Pillow/Matplotlib；工程上当然可以用 OpenCV。

**Q2：为什么用 BT.601 全范围，而不是 16–235？**  
A：输入是普通 8 位 sRGB PNG，没有视频编码的头部/范围信息；full-range 的 `Y` 覆盖 0–255，`Cb/Cr` 以 128 为中心，和常见肤色阈值（77–127、133–173）一致。

**Q3：椭圆判据为什么不用开方？**  
A：只需判断点在椭圆内还是外，`(u/a)²+(v/b)² <= 1` 与开方后的距离等价；省掉 `sqrt` 的开销，判断也更直接。

**Q4：中值滤波为什么能去噪？**  
A：对二值掩膜，5×5 中值就是多数投票。孤立的一个白点周围最多只有少量白点，投不过半，被清掉；实心区域内部白点占多数，保留。

**Q5：为什么边界用 edge padding？**  
A：补 0 会把图像外侧当成背景，贴边的实心肤色区域会被腐蚀；复制边缘像素可以保持边界的投票结果，输出尺寸也不变。

**Q6：float32 精度够吗？**  
A：颜色值只有 8 位，float32 约 7 位有效数字，做线性组合、gamma、立方根足够；比 float64 省一半内存和带宽。

**Q7：LAB 的旋转角为什么看不出效果？**  
A：默认半轴是 `(13,13)`，椭圆退化成圆，旋转圆不会改变形状。要看到旋转效果，需要把两个半轴设成不同值。这是当前参数的一个可改进点。

**Q8：RGB 球为什么在 `asian_6` 上选中了大部分像素？**  
A：球心取整幅图平均色，低照度深色背景占比大，球心被拉向背景；半径 100 又很大，结果把背景和暗部一起圈进去（选中 82.57%，四角误检 97.21%）。它不是肤色模型，只是「接近平均色」的区域。

**Q9：HSV 的色相跨 0° 怎么办？**  
A：当前 `HSVSplit` 只判断 `0°–50°`，没有实现回绕；对这批亚洲肤色够用。若要覆盖 350°–360° 的红色，需要加 `wrap_hue` 分支：`(H >= lo) | (H <= hi)`。

**Q10：如何进一步提升？**  
A：人脸检测或皮肤先验限定区域；按图像自适应阈值；形态学开闭运算；连通域保留最大肤色块；用少量标注数据学习椭圆/高斯参数。

**Q11：为什么 `main()` 里 mask 算了两次？**  
A：一次用于显示，一次在 `colorspace_split` 内部用于生成结果。是接口设计造成的小冗余；可以抽出一个 `apply_mask(view, mask)`，让 `colorspace_split` 接受预计算掩膜。

**Q12：复杂度是多少？**  
A：颜色转换和阈值判断都是 `O(H×W)`；中值滤波是 `O(H×W×k²)`，5×5 时 `k²=25`。整幅 640×512 的图像在 NumPy 下是毫秒级。

| 位置 | 现状 | 建议 |

## 14. 最后记住这四句

1. **颜色空间解决「肤色在哪里聚得更紧」**：YCbCr/HSV/LAB 都比 RGB 更适合。
2. **判决边界解决「怎么把簇圈出来」**：框最简单，旋转椭圆最贴合，球最容易受背景影响。
3. **中值滤波解决「掩膜里的孤立噪点」**：二值中值 = 多数投票，edge padding 保边界。
4. **统一接口解决「怎么组织代码」**：`Split.mask` 把变化封装起来，`colorspace_split` 只负责应用。
